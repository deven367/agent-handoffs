# Priority 1 — Q8_K_XL at native 262K on one L40S

## Goal

Serve `/scratch/local/demistry/models/Qwen3.8-27B-UD-Q8_K_XL.gguf` through tinygrad with a `262144`-token window on the single L40S. Preserve Q8_K_XL weights. First make it fit correctly; then make long-prompt prefill useful.

This is the primary project. Q4_K_M is only the control and fallback.

## Starting state

- Host: `node-lair`; L40S reports `46068 MiB` / `44.99 GiB`.
- Source: `/u/demistry/tinygrad-src`, branch `qwen27b-nv-q8-kernel`.
- Current source commit: `1d8b8cab7` on `fork/qwen27b-nv-q8-kernel`.
- Q8_K_XL works at context 512 and through the server at context 4096.
- Measured Q8 server usage at context 4096: `34316 MiB` by `nvidia-smi`.
- tinygrad allocates `cache_kv` as FP16 in `TransformerBlock._init_state`.
- Full FP16 KV at 262K is exactly 16 GiB; Q8_K_XL + FP16 KV cannot fit safely.
- Tracked Makefile currently defaults to Q8_K_XL and `TG_CTX=262144`; plain `make serve-tg` is therefore expected to OOM until this plan lands. Do not use it as a readiness check.
- Recurrent CUDA/NV inference forces `chunk_size=1`; retain that guard during cache work.

## Memory budget

Model: 16 full-attention blocks, 4 KV heads, K/V head dimension 256.

```text
values = 2 * 16 * 4 * 262144 * 256 = 8,589,934,592
```

| Cache | Storage | Exact cache size | Projected server total from measured 4096 baseline |
|---|---|---:|---:|
| FP16 | 2 B/value | 16.0 GiB | >45 GiB; does not fit |
| Q8_0 | 34 B/32 values | 8.5 GiB | ~41.8 GiB; narrow ~3.2 GiB headroom |
| Q4_0 | 18 B/32 values | 4.5 GiB | ~37.8 GiB; preferred production headroom |

Use `nvidia-smi` for capacity acceptance. tinygrad's `GlobalCounters.mem_used` excludes several GiB visible to the driver.

## Required outcome

- `make serve-tg` can start Q8_K_XL at 262144 without allocator retry or OOM.
- Peak GPU usage is below 42 GiB for Q8_0 and below 40 GiB for Q4_0.
- Quantized-cache logits remain finite and close to FP16 at context 4096.
- Greedy token sequence matches FP16 over the agreed validation prompt.
- Prefix reuse and divergent-prompt reset match a cold run.
- Prompt plus completion cannot exceed 262144.
- One request slot only. Concurrency is out of scope.

## Phase 1 — Add an explicit cache format contract

### Interface

Add one cache-format value flowing from CLI to attention blocks:

```text
--cache-type f16|q8_0|q4_0
```

Recommended ownership:

- `tinygrad/llm/cli.py`: parse and pass the value.
- `Transformer.from_gguf`: validate backend/model support and put it in `TransformerConfig`.
- `TransformerBlock._init_state`: allocate the selected cache layout.
- `TransformerBlock._attention`: write new K/V rows and route to the matching attention consumer.

Keep `f16` as the library default. The Makefile may choose `q4_0` after it is verified. Reject unsupported cache/backend combinations explicitly; do not silently fall back to FP16.

### Layout

Use compact persistent storage, not the existing GEMV activation scratch layout.

Q8_0 per 32 values:

```text
scale: float16
quants: 32 signed int8
```

Suggested logical shapes per K/V cache:

```text
quants: (2, batch, kv_heads, max_context, head_dim)
scales: (2, batch, kv_heads, max_context, head_dim/32)
```

A packed `uint32` physical view is fine if it remains exactly 32 bytes per group. Do not reuse `_q8_quantize`'s oversized all-lanes scratch tensor as persistent cache.

Q4_0 production layout must match llama.cpp exactly: 16 packed quant bytes plus one FP16 scale per 32 values. Read the current llama.cpp quantize/dequantize functions before coding; do not infer rounding or signed-range behavior.

## Phase 2 — Implement append-only cache quantization

Start with Q8_0 because it is the simplest correctness milestone.

Requirements:

1. Quantize only `start_pos:start_pos+T`.
2. Compute one scale per group of 32 values.
3. Define zero-group behavior without NaN/Inf.
4. Clamp and round exactly once.
5. Preserve K and V independently.
6. Reset/reuse behavior remains driven by existing position and cache-prefix logic.
7. No temporary allocation proportional to `max_context` during an append.

Leave the recurrent SSM state unchanged; only 16 full-attention blocks own KV caches.

Small retained test cases must cover:

- all-zero group
- positive/negative extrema
- non-multiple append positions
- offsets 0, 1, 31, 32, 33
- multiple appends producing the same bytes as one combined append

Test observable dequantized values and attention output, not internal field copies.

## Phase 3 — Consume packed cache directly in NVIDIA attention

Generic `scaled_dot_product_attention` expects dense tensors, so quantized KV needs a tiled consumer. Never dequantize the full history into a dense Tensor.

Implement decode first (`T=1`), because the existing recurrent guard keeps prefill scalar. Reuse:

- online-softmax structure from `tinygrad/llm/kernels/amd.py` flash-attention kernels
- NVIDIA warp reduction primitives from `tinygrad/llm/kernels/nv.py`
- existing GQA mapping: 24 query heads / 4 KV heads = 6 query heads per KV head

Kernel behavior:

1. Load one packed K tile and its scales.
2. Dequantize in registers/shared memory.
3. Accumulate query-key scores in float32.
4. Apply stable online softmax across the valid prefix.
5. Load/dequantize V tiles and accumulate output in float32.
6. Never read beyond `valid_kv_len` except explicitly zero/masked physical padding.
7. Return the same `(B, H, 1, D)` contract as current attention.

Do not add a generic abstraction for hypothetical cache formats. One Q8_0 path, one FP16 path; add Q4_0 only after Q8_0 validates.

## Phase 4 — Validate Q8_0 before full context

### Kernel-level A/B

Compare packed-cache attention to FP16 attention on deterministic random data:

- prefix lengths: 1, 31, 32, 33, 127, 128, 129, 511
- query heads 24, KV heads 4, head dimension 256
- zero and high-dynamic-range K/V groups

Report max absolute error, relative error, and correlation. Set tolerance from observed Q8_0 error; do not require bit identity.

### Full-model A/B at context 4096

Run the same prompt with FP16 and Q8_0 cache:

- compare raw next-token logits
- require finite outputs
- record max absolute error and correlation
- compare at least 32 greedy tokens
- compare cold run, shared-prefix reuse, and divergent-prompt reset

### Memory gate at context 262144

Only after 4096 A/B passes:

```bash
python3 -m tinygrad.llm \
  --model /scratch/local/demistry/models/Qwen3.8-27B-UD-Q8_K_XL.gguf \
  --max_context 262144 --cache-type q8_0 --warmup
```

Acceptance:

- warmup completes
- `nvidia-smi` peak <42 GiB
- no allocation fallback/retry
- one short API request succeeds
- shutdown releases GPU memory

If Q8_0 exceeds the budget, profile actual owners before starting Q4_0; do not guess.

## Phase 5 — Add Q4_0 for production headroom

Mirror llama.cpp's exact Q4_0 cache quantization and tile dequantization. Reuse the validated Q8_0 routing and attention structure; only storage, quantization, and tile decode should differ.

Repeat all kernel/full-model A/B tests. Quantization error will be larger, so record:

- logit max error and correlation
- greedy-token divergence position over at least 128 tokens
- prompt classes: normal text, code, repeated tokens, and long repeated-prefix cache reuse

Production acceptance:

- Q8_K_XL server starts at 262144
- peak <40 GiB
- at least 4 GiB free after warmup
- no non-finite logits
- quality results documented beside FP16 and Q8_0

Then set:

```make
TG_MODEL ?= /scratch/local/demistry/models/Qwen3.8-27B-UD-Q8_K_XL.gguf
TG_CTX   ?= 262144
TG_KV    ?= q4_0
```

and pass `--cache-type $(TG_KV)`.

## Phase 6 — Make 262K operationally useful

Quantized KV solves fit, not prefill. After Q4_0 server acceptance, execute the shared prefill work in `09-2026-09-06-q4-262k-prefill-plan.md`, using Q4_K_M first as the cheaper control. Port the proven changes to Q8_K_XL and re-run memory gates because Q8 has less headroom.
